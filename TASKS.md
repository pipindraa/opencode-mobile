# Задачи по приложению (список от владельца, 30.10.2026)

Живой тест на телефоне недоступен (Omnirush сервер требует обновления, ADB отвалился),
поэтому правим код и собираем APK без проверки на устройстве. Статусы обновляются по ходу.

## 1. Индикатор «запрос работает»
Сейчас в чате виден только маленький спиннер в хедере, в остальном — тишина.
Нужно: заметный статус процесса (думает / печатает / вызывает инструмент / ждёт разрешения),
таймер, плавные «бегущие» точки, блокировка кнопки отправки без объяснений.

## 2. Отправка картинок с телефона
Нет выбора фото и вложений. Нужно: кнопка 📎 → галерея → превью → отправка вместе с текстом.
Разобраться, как это принимают оба API (OpenCode v2 и форк Omnirush).

## 3. Клавиатура перекрывает поле ввода
При открытии клавиатуры панель ввода уезжает под неё. Нужно как в Telegram:
панель ввода поднята над клавиатурой, лента сообщений сжимается, а не уезжает.

## 4. Авто-обновления без похода к разработчику
Хочется ставить новую версию прямо из приложения. Кандидат — GitHub Releases
(gh CLI уже залогинен как pipindraa). Проверить варианты лучше GitHub-релизов.

## 5. Заголовок чата
Сверху написано «kiril» (это имя пользователя). Нужно имя/название чата.

## 6. Свайп вправо из чата → список чатов
Свайп от левого края вправо (как «назад» в iOS). Сейчас выйти можно только кнопкой
«‹ Назад» и системной кнопкой Android.

## 7. Tailscale убивает интернет на телефоне
Без VPN не подключиться, с VPN — интернета нет. Продумать альтернативы
(раздельное туннелирование, собственный туннель, другой транспорт).

## 8. Откат сообщений и отмена текущего запроса
- Откат (revert) как в OpenCode: удалить сообщения начиная с последнего запроса.
- Отмена (как Esc Esc): мгновенно остановить агента.

## v1.6.4 (04.11) — голос: ИСТИННЫЙ root cause (два экземпляра Voice)
На телефоне 1.6.3, logcat подтверждал: распознаватель РАБОТАЕТ

- VoicePackage всегда создаёт VoiceModule. У VoiceSpec (newarch) СВОЙ
  `private val voice = Voice(context)`, и у VoiceModule СВОЙ — ДВА
  экземпляра распознавателя.

  распознавание идёт в экземпляре #2 (его lastResults получает текст из
  onResults/onPartialResults).
- getSpeechResults в VoiceModule НЕ был переопределён → вызов падал в
  VoiceSpec.getSpeechResults → читал lastResults экземпляра #1 = ВСЕГДА "".
  JS-поллинг получал пусто → «голос не работает».
ФИКС (VoiceModule.kt, патч): override getSpeechResults → голос.
getSpeechResults(callback) — все методы читают один и тот же экземпляр, где
идёт распознавание. Плюс Log.d в Voice.getSpeechResults (textLen/err) для
logcat-проверки.

## v1.6.5 (04.11) — непрерывная диктовка (пауза не рвёт текст)
Владелец: голос РАБОТАЕТ, но «когда перестаю разговаривать — он
автоматически сбрасывается». Причина: нативная сессия SpeechRecognizer

ФИКС (только JS, нативка не менялась):
- voice.ts: в start() добавлены EXTRA_SPEECH_INPUT_COMPLETE_SILENCE_LENGTH_MILLIS=3000

  нативная сессия переживает паузу до 3с (Voice.kt читает их getDouble).
- ChatScreen (useEffect голоса, полный rewrite) — непрерывный режим:
  - accum: распознанное копится ЧЕРЕЗ сессии (нативка сбрасывает lastResults

    приходит ~80мс ПОСЛЕ onEndOfSpeech) → текст докидывается в accum.

  - пауза ≤ 2с от последнего текста (VOICE_SILENCE_GRACE_MS < нативных 3с)
    → АВТО-РЕСТАРТ voiceNative.start("ru-RU") — диктовка идёт дальше.
    Неудача рестарта → финал с ошибкой (если за это время подтянулась
    новая сессия — не убиваем её: isRecognizing guard).

    сессия), раньше — только по ⏹ (stoppingRef → сразу onSessionEnd)

  - tick 400мс (было 700); watchdog 45с = «НЕТ ПРОГРЕССА» (сбрасывается на
    каждом конце сессии и на каждом новом partial) — длинную диктовку

## v1.7.5 (10.11) — чипы и инфо-строка: явные высоты по честному замеру

**Честно: 1.7.3 и 1.7.4 чинили не тот механизм.**
- 1.7.3: я прочитал первый скрин как «крупный шрифт (font_scale ~3.5)» —
  на деле у телефона владельца **font_scale = 1.1** (проверено через adb:
  `settings get system font_scale`, Samsung M52, 420dpi, Android 13).
  Диагностика была ошибочной.
- 1.7.4 (onLayout чипа): фикс был **циркульным** — чип мерялся внутри уже
  сломанной строки и возвращал в неё же свою вжатую высоту. Телефон
  владельца на 1.7.4 подтвердил: чипы по-прежнему ~30px, без текста.
  Плюс мой smoke-тест 1.7.4 смотрел только экран настроек, чат не открывал —
  проверять надо было чат.

**Настоящий механизм (из кода + пикселей):** клипятся ОБЕ горизонтальные
строки — чипы фраз внизу И инфо-строка сверху (селекторы модель/агент/
токены) — т.е. это не про конкретные чипы, а про **горизонтальные
ScrollView, которые сами неправильно считают свою авто-высоту** в этом
RN (0.88, Fabric) и сжимаются до ~30px, вжимая чипы (текст обрезается до
ничего, видна пустая «пилюля»).

**Фикс (ChatScreen.tsx, сборка 10705) — ФИНАЛЬНЫЙ, детерминированный:**
- Первый вариант 1.7.5 использовал невидимый «пробник» (Text absolute +
  onLayout) для замера высоты строки. Живой чат на эмуляторе при
  font_scale 1.1 показал: **onLayout не срабатывал** (lineH оставался 0 →
  явные высоты не применялись → строки клипались как раньше). onLayout —
  ненадёжный механизм: зависит от layout-прохода, второй рендер, может
  тихо не прийти.
- **Итоговый фикс не использует onLayout вообще.** Высота строки текста
  считается **синхронно** из системного масштаба шрифта:
  `lineH = ceil(fontSize.s × PixelRatio.getFontScale() × 1.4)`.
  `PixelRatio.getFontScale()` — это и есть `font_scale` Android
  («размер текста», у владельца 1.1) — читается нативно, без layout,
  без колбэка, **не может тихо сломаться**.
- **Явные высоты** всем, что клипалось (border-box RN: `height` включает
  padding и рамку):
  - чипы фраз + чип «Фразы»: `height: chipH`, `chipH = lineH + 14`;
  - строка фраз (HVS): `height: chipH + spacing.xs`;
  - чипы инфо-строки (модель/агент/файлы/токены): `height: chipH`;
  - инфо-строка: `height: chipH + spacing.xs`, её HVS: `height: chipH`.
  Авто-высота (то, что ломалось) из вертикали полностью убрана —
  сжиматься нечему. Закрывает обе строки разом (чипы + «обрезанная
  иконка» сверху).
- При font_scale 1.1: `lineH = ceil(13 × 1.1 × 1.4) = 20dp`, `chipH = 34dp`,
  строка ≈ 38dp ≈ 100px (420dpi) — против сломанных ~30px.

## v1.7.6 (11.11) — чипы в чате: ничего не режется (верх и низ)

**Диагноз по скрину владельца 1.7.5 (1080×2400, 420dpi), по пикселям, не
гаданием:**
- **Верх** — НЕ вертикаль (высота строки 90px = 34.3dp — правильная, фикс
  1.7.5 сработал). Это **горизонтальный overflow**: `HVS(модель+агент+файлы)
  + жёсткий чип токенов справа`. На телефоне модель длинная
  `logfare/glm-5…` (417px = maxWidth 160dp) + токены `32.0M в · 2.1M из · $0`
  (464px = 177dp, `flexShrink:0`). Экран 411dp − padding 32dp = 379dp;
  модель 160dp + токены 177dp = 337dp, на агент+файлы остаётся ~42dp —
  агент-чип (иконка) срезан правым краем HVS без шеврона, «Файлы» за краем
  совсем. На эмуляторе модель была короткая «модель…» и токены «0» — влезло,
  поэтому 1.7.5 на эмуляторе не воспроизвёл условия владельца.
- **Низ** — чипы фраз **вертикально клипнулись**: на телефоне чип 74px
  (2042..2115) **без рамок** сверху/снизу; на эмуляторе (тот же билд, fs 1.1)
  те же чипы **полные 91px с обеими рамками** (1647..1649 и 1736..1738).
  Разница в структуре: верхняя строка = `View(height) → HVS(height) → чипы`
  (у владельца работает), нижняя = «голый» `ScrollView(height + paddingBottom)
  → чипы` (у владельца клипается). Android-Scrollview-контейнер с явной
  высотой + padding в этом RN сжимает/клипает вертикаль; обёртка View с
  высотой — нет.

**Фикс (ChatScreen.tsx, сборка 10706) — структурный, не нащупыванием
размеров:**
- **Верх:** все 4 чипа (модель/агент/файлы/токены) — в **одном** HVS
  (токены перенесены из жёсткой зоны справа внутрь скролла). Чипы больше не
  режутся рамкой контейнера: не хватает места — строка скроллится (как строка
  фраз). Модель по-прежнему с эллипсисом (`maxWidth:160` + `numberOfLines:1`),

  Убран мёртвый стиль `chipFixed` (flexShrink:0) и бессмысленный `gap` в
  `infoRow` (остался один ребёнок).
- **Низ:** структура приведена к рабочей верхней — `View(height) →
  ScrollView(height) → чипы`. «Голый» ScrollView с явной высотой убран.
